WebPerf Tips · Bài 15 · Network

Transfer size và resource size

Nén và cache làm giảm byte qua mạng, nhưng CPU người dùng vẫn phải xử lý toàn bộ kích thước thật của file.

Bài gốc: “Transfer Size vs. Resource Size” ↗
00 · HAI CON SỐ

Cùng một file, hai kích thước

Transfer Size

Tổng byte phải đi qua mạng (“bytes over the wire”), gồm payload và header request/response. Càng lớn thì truyền càng lâu.

Resource Size

Tổng byte của chính tài nguyên, không liên quan tới mạng, bất kể có nén hay cache hay không. Càng lớn thì CPU xử lý càng lâu.

app.js · 120 kB─nén brotli→qua mạng · 32 kB─giải nén→120 kB trên máy người dùng
Resource size 120 kB, transfer size 32 kB (số minh hoạ)
01 · GIẢM TRANSFER SIZE

Nén và cache

Nén

Server hoặc bước build nén tài nguyên bằng gzip / brotli trước khi gửi. Byte đi qua mạng ít hơn nhiều, nhưng trình duyệt phải giải nén trước khi xử lý tiếp.

Cache

Tài nguyên nằm sẵn trong browser cache thì không cần truyền byte nào: transfer size bằng 0. Đó là lý do cache là tối ưu phổ biến đến vậy.

02 · CHI PHÍ CỦA RESOURCE SIZE

“Đã cache rồi thì không sao”: sai

Nhiều người tin rằng tài nguyên được gửi tối ưu hay đã cache thì không thể làm chậm trang. Thực tế, ngay khi tài nguyên tới trình duyệt (từ mạng hay từ cache), chi phí CPU mới bắt đầu, và chi phí đó tỉ lệ với resource size. Máy người dùng thường yếu hơn máy lập trình viên, nên hậu quả càng nặng.

JavaScript

File JS 120 kB sau giải nén phải được parse, compile, execute trên máy người dùng, dù nó tải nhanh hay lấy từ cache (bài 24).

Ảnh

Ảnh phải được decode trước khi hiện lên màn hình, dù tải nhanh hay lấy từ cache.

03 · GIẢM RESOURCE SIZE

Cắt bớt chính tài nguyên

  • Minify JS và CSS (bài 17).
  • Chọn định dạng ảnh tối ưu.
  • Code splitting JavaScript.
  • Lazy load tài nguyên chưa cần ngay.

Parse và compile file JS 15 kB nhanh hơn hẳn file 120 kB.

Khi thêm thư viện mớiMột thư viện quảng cáo “chỉ N kB” thì hỏi lại: N kB đã nén hay N kB thật? CPU người dùng trả giá theo con số thật.
04 · LỢI KÉP

Giảm resource size thì transfer size giảm theo

Transfer size thường là bản nén của resource, nên resource nhỏ thì bản nén còn nhỏ hơn. Ví dụ minh hoạ: cắt file JS từ 120 kB xuống 15 kB vừa giảm mạnh chi phí CPU, vừa khiến bản nén chỉ còn khoảng 5–6 kB thay vì khoảng 32 kB.

05 · ĐO

Ở đâu xem được hai con số

  • Tab Network: cột Size và popup khi hover (bài 13).
  • Track Network trong Performance panel (bài 14).
  • Ngoài thực tế: Resource Timing API cho mỗi tài nguyên có transferSize, encodedBodySize, decodedBodySize.
for (const r of performance.getEntriesByType('resource')) {
  console.log(r.name, 'qua mạng:', r.transferSize, 'thật:', r.decodedBodySize);
}
  • Transfer size → thời gian mạng; giảm bằng nén và cache.
  • Resource size → thời gian CPU; cache không cứu được.
  • Giảm resource size là tối ưu cả hai phía.
