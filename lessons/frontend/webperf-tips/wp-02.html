Rendering pipeline: từ HTML/CSS tới pixel

DOM, CSSOM, Render Tree, Style, Layout, Paint: trình duyệt làm gì trước khi bất kỳ pixel nào xuất hiện.

Bài gốc: “An Introduction to the Browser Rendering Pipeline” ↗
00 · BỨC TRANH CHUNG

Người dùng chỉ thấy pixel

Một ứng dụng “cảm giác nhanh” khi pixel (frame) lên màn hình sớm. Nhưng thứ ta viết là HTML và CSS dạng chữ, và quá trình trình duyệt biến chúng thành pixel thì gần như vô hình với lập trình viên. Vì không thấy nên ít ai nghĩ tới việc nó chạy khi nào và tốn bao nhiêu. Bài này đi qua phiên bản đơn giản của quy trình đó.

HTML text→DOM + CSS text→CSSOM →Style → Render Tree→Layout→Paint → Pixel
Các chặng chính của rendering pipeline (bản cho người mới)

01 · HTML PARSING

Văn bản HTML thành cây DOM

Khi người dùng mở trang, thứ đầu tiên trình duyệt nhận là tài liệu HTML dạng văn bản. HTML Parser đọc văn bản này và dựng DOM (Document Object Model): một cây mà mỗi node là một object của trình duyệt, ứng với một phần trong file HTML.

<!DOCTYPE html>
<html>
  <head>
    <title>Cửa hàng</title>
    <link rel="stylesheet" href="shop.css">
  </head>
  <body>
    <h1>Sản phẩm</h1>
    <p>Áo thun</p>
    <p>Quần jean</p>
  </body>
</html>
document
└─ html
   ├─ head
   │  ├─ title ─ "Cửa hàng"
   │  └─ link (shop.css)
   └─ body
      ├─ h1 ─ "Sản phẩm"
      ├─ p  ─ "Áo thun"
      └─ p  ─ "Quần jean"
Cây DOM dựng từ đoạn HTML trên

Việc parse HTML chạy như một task trên main thread; trong Performance panel nó hiện thành task Parse HTML.

02 · CSSOM

Stylesheet thành cấu trúc tra cứu nhanh

HTML lo cấu trúc, còn CSS lo trình bày. Stylesheet thường đến từ thẻ <link rel="stylesheet">, cũng có thể nằm inline trong <style>.

Stylesheet là tập các rule. Mỗi rule gồm selector (chọn phần tử nào) và các declaration (gán thuộc tính gì):

/* cả khối là một rule */
p {                      /* selector */
  color: navy;              /* declaration */
}

Một trang có thể có nhiều stylesheet, mỗi cái nhiều rule, mỗi rule nhiều declaration. Trình duyệt parse tất cả rồi gộp vào CSSOM (CSS Object Model), một cấu trúc dữ liệu tiết kiệm bộ nhớ và tối ưu cho việc tra: “selector này khớp với những style nào?”.

Parse stylesheet cũng là task trên main thread, hiện trong trace là Parse Stylesheet.

Ghi chúCấu trúc bên trong CSSOM khác nhau giữa các trình duyệt. Cứ hình dung nó là một cây tối ưu cho tra cứu nhanh; ai tò mò có thể đọc mã nguồn StyleEngine của Chromium.

03 · STYLE & RENDER TREE

Ghép DOM với CSSOM

Khi đã có DOM và CSSOM, trình duyệt sang pha Style, còn gọi là Recalculate Style hay Render Tree Update.

Render Tree

Render Tree (hay Layout Tree) là cấu trúc C++ nội bộ của trình duyệt, lập trình viên không sửa trực tiếp. Nó là cây riêng nhưng thường có hình dạng giống DOM. Mỗi node thường trỏ tới một DOM node và một ComputedStyle, và cây chỉ chứa những gì thực sự được hiển thị.

// Phác thảo một node của Render Tree (đơn giản hoá)
struct RenderNode {
  DomNode*       source;     // node DOM mà nó đại diện
  ComputedStyle* style;      // style đã tính xong cho node đó
  RenderNode*    parent;
  RenderNodeList children;
};

Render Tree còn quản lý những thứ hiển thị không đến từ DOM như thanh cuộn hay vùng bôi chọn chữ. Ngược lại, những gì không lên màn hình thì không có mặt: <head> và con của nó, <script>, và phần tử display: none.

ComputedStyle

ComputedStyle là danh sách declaration cuối cùng áp lên một node. Ví dụ phần tử <p class="price"> với CSS:

p      { color: navy; }
.price { font-weight: 700; color: crimson; }

Trình duyệt sẽ:

  1. Tra CSSOM để tìm mọi rule có selector khớp với phần tử.
  2. Giải quyết xung đột theo độ ưu tiên (specificity). Ở đây .price thắng p, nên kết quả là color: crimson, font-weight: 700, cộng với các style mặc định của trình duyệt.

Dựng cây

Để dựng Render Tree, trình duyệt duyệt đệ quy DOM, tìm các phần tử hiển thị, tạo hoặc cập nhật node tương ứng, rồi tính ComputedStyle và gắn vào. Kết quả là một Render Tree đã có style đầy đủ. Trong Chromium Profiler, bước này hiện là task Recalculate Style.

04 · LAYOUT

Gán hình học cho từng node

Render Tree đã biết mọi thuộc tính width, height, màu… nhưng chưa phần tử nào có toạ độ hay kích thước thật. Pha Layout (còn gọi là Reflow) duyệt đệ quy Render Tree và gán cho mỗi node một hộp với vị trí, kích thước chính xác (số thực).

Với ví dụ cửa hàng ở trên:

  • body là block nên rộng bằng màn hình.
  • Muốn biết chiều cao của body, trình duyệt phải đi xuống các con: h1 và hai p (đều là block).
  • Chiều cao mỗi block lại phụ thuộc vào text node bên trong.
  • Chiều cao được cộng dồn ngược lên, và toạ độ chính xác được gán cho từng hộp.

Layout có thể rất tốn kém, nên trình duyệt cache kết quả kỹ để tránh tính lại khi không cần. Thường nó hiện trong pha rendering của profiler; nhưng nếu bạn gây ra forced synchronous reflow, Layout sẽ xuất hiện ngay bên trong một task JavaScript (xem bài 23).

05 · PAINT

Vẽ thành pixel

Có Render Tree đã style và định vị, trình duyệt dùng thư viện đồ hoạ để vẽ từng node thành pixel. Nó duyệt đệ quy cây và phát lệnh vẽ, đảm bảo đúng thứ tự vẽ (xử lý z-index, vùng cuộn…).

Chromium dùng thư viện Skia, Skia lại nói chuyện với GPU qua OpenGL/DirectX. Khi GPU tạo xong texture, trình duyệt gom lại thành một Frame và gửi ra màn hình.

Paint đặc biệt ở chỗ công việc trải qua nhiều luồng và tiến trình, nhưng trên main thread bạn sẽ thấy mục Paint trong profiler. Phần nâng cao về layer và compositing nằm ở bài 27.

06 · KHI NÀO CHẠY

Rendering chạy lúc nào?

Ta đã biết rendering làm gì; còn khi nào thì do event loop quyết định: nó chen task render steps giữa các task thường khi cần frame mới (xem lại bài 01).

  • HTML → DOM; CSS → CSSOM; cả hai là task trên main thread.
  • Style ghép hai cây thành Render Tree, mỗi node có ComputedStyle.
  • Layout gán vị trí, kích thước; Paint vẽ ra pixel và tạo frame.
  • CSS, HTML hay component React đẹp tới đâu cũng chưa hiện được cho tới khi các pha này chạy xong.
