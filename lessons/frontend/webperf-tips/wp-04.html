Long Task: vì sao task trên 50 ms làm trang khựng

Một task dài chặn cả hàng đợi lẫn render steps: frame đầu tiên đến muộn, gõ phím bị giật.

Bài gốc: “Long Tasks: What they are and why you should avoid them” ↗
00 · ÔN LẠI

Một luồng, quá nhiều việc

Main thread của trang phải gánh: xử lý input (click, phím), chạy JavaScript (React, logic nghiệp vụ) và tạo frame. Tất cả đều là task, và chỉ một task chạy tại một thời điểm. Nên bất kỳ task nào chạy quá lâu cũng làm nghẽn cả luồng.

Cần nắm trước: event loop (bài 01). Nên biết sơ qua Performance panel (bài 06).

02 · TÁC HẠI

Chặn event loop, chặn luôn frame

Khi một task đang chạy, event loop không thể lấy task nào khác từ hàng đợi ra. Long task vì thế giữ cả hàng đợi đứng yên trong một khoảng dài: click, phím, timer… đều phải chờ.

Render steps cũng chỉ là một task, nên cũng phải chờ. Task dài đồng nghĩa frame tiếp theo bị đẩy lùi:

Cùng một thay đổi UI, frame đến muộn hơn hẳn khi task dài

Vấn đề 1: frame đầu tiên đến muộn

Nếu UI ban đầu do JavaScript dựng (React, Vue…), thì người dùng chỉ thấy giao diện khi: framework dựng xong DOM → render steps chạy → frame được tạo. Task dựng DOM càng dài, màn hình trắng càng lâu. Rút ngắn task đó là đưa frame quan trọng nhất đến sớm hơn.

Vấn đề 2: nhập liệu bị giật

Khi người dùng gõ vào ô input, mỗi phím là một task được xếp hàng, chạy, rồi một frame vẽ ký tự mới. Bình thường nhịp “phím → frame → phím → frame” đều đặn nên gõ thấy mượt.

03 · NGUYÊN NHÂN

Long task thường đến từ đâu

Phần lớn là đoạn JavaScript nặng hoặc kém hiệu quả chạy đồng bộ trong một task:

  • Vòng for/while lặp rất nhiều lần.
  • Việc đồng bộ lặp đi lặp lại: parse, decode, nối chuỗi; cập nhật DOM; compile script lớn.
  • Đọc thông tin vị trí phần tử sai cách, gây layout thrashing (bài 23).
  • Microtask nặng hoặc dồn dập, thường từ Promise resolve liên tiếp.

Long task không chỉ do JavaScript, nhưng trên thực tế JavaScript là thủ phạm phổ biến nhất.

04 · TÌM TRONG PROFILER

Chrome đánh dấu sẵn cho bạn

Ghi một trace (bài 05) rồi nhìn track Main: Chromium Profiler tô tam giác đỏ ở góc và gạch chéo phần vượt 50 ms của mỗi long task. Bên dưới mỗi task là flamegraph; đọc nó (bài 08–10) để tìm đoạn code chậm.

▣Ảnh/ví dụ gốc ảnh profiler đánh dấu Long Task↗
  • Task > 50 ms là long task; nó chặn hàng đợi và chặn render steps.
  • Hệ quả: UI ban đầu hiện muộn, input phản hồi chậm (jank).
  • Hướng xử lý: bỏ việc thừa trong task, hoãn việc không quan trọng ra khỏi đường găng, và chia task lớn thành nhiều task nhỏ.
