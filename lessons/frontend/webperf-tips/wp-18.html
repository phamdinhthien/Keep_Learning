WebPerf Tips · Bài 18 · Network

Hai điểm nghẽn mạng phổ biến

Vòng đời một request, Resource Timing API để định lượng từng pha, và hai “hình dạng” request hay gặp: chờ lâu và tải lâu.

Bài gốc: “Identifying Common Network Bottlenecks” ↗
00 · VÒNG ĐỜI REQUEST

Mọi request đều đi qua cùng các pha

Dù là request HTML đầu tiên hay một file JS con, request nào cũng trải qua cùng chuỗi pha. Bỏ qua redirect (và App Cache đã lỗi thời), ta quan tâm bốn pha:

DNS→TCP (+TLS)→Gửi request, chờ phản hồi→Nhận response
Mỗi pha có mốc bắt đầu/kết thúc mà trình duyệt ghi lại

Cần biết trước track Network (bài 14) và tab Network (bài 13).

▣Ảnh/ví dụ gốc sơ đồ các pha và mốc thời gian của một request↗
01 · RESOURCE TIMING

Trình duyệt đã ghi sẵn mốc của từng pha

// request tài liệu ban đầu
const nav = performance.getEntriesByType('navigation')[0];
// các tài nguyên con: JS, CSS, ảnh, fetch…
const subs = performance.getEntriesByType('resource');

Mỗi entry có các mốc (ms). Giả sử một request trang chủ của shop cho ra:

{
  domainLookupStart: 3,   domainLookupEnd: 6,     // DNS
  connectStart:      6,   connectEnd:      15,    // TCP
  requestStart:      15,  responseStart:   740,   // chờ phản hồi
  responseEnd:       820,                            // tải xong
  entryType: 'navigation', startTime: 0               // navigation luôn bắt đầu ở 0
}

Nhìn bảng là thấy nghẽn ở pha chờ phản hồi. Gửi các con số này về telemetry để có dashboard phản ánh người dùng thật.

03 · NGHẼN 1

Chờ phản hồi quá lâu

Hình dạng: khối nhạt rất dài, khối đậm ngắn. Trong Resource Timing là khoảng cách lớn giữa requestStart và responseStart. Nguyên nhân thường gặp:

  • Backend chậm: mất nhiều thời gian để tạo ra response.
  • Backend ở xa: đường đi tới server và đường báo về đều dài.
04 · NGHẼN 2

Tải về quá lâu

Hình dạng ngược lại: server trả lời nhanh, nhưng payload lớn nên khối đậm (tải) dài. Trong Resource Timing là khoảng cách lớn giữa responseStart và responseEnd. Hay gặp với CDN: phản hồi rất nhanh nhưng phải chuyển ảnh, file JS lớn. Thời gian tải phụ thuộc trực tiếp vào transfer size, nên hãy tối ưu nó (bài 15–17).

▣Ảnh/ví dụ gốc ảnh hai dạng request trong profiler↗
  • getEntriesByType('navigation' | 'resource') cho mốc của từng pha.
  • Chờ lâu → nhìn backend (tốc độ, khoảng cách).
  • Tải lâu → giảm transfer size.
