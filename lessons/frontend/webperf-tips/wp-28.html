Animation mượt nhờ compositor thread

Animation giật thường vì nó phụ thuộc main thread. Khai báo đúng cách để compositor tự chạy 60 FPS bất kể JavaScript bận cỡ nào.

00 · MỤC TIÊU

60 frame mỗi giây, đều đặn

Ứng dụng dùng animation khắp nơi: màn hình chờ khi khởi động, spinner khi một module đang tải… Để mắt người thấy mượt, animation phải tạo frame đều đặn ở 60 FPS. Không giữ được nhịp đó thì animation trông giật và chậm. Bài gốc có ví dụ so sánh trực quan hai spinner, một mượt, một giật.

01 · NGUYÊN NHÂN

Animation đang dựa vào main thread

Nếu animation giật, rất có thể cơ chế chạy nó phụ thuộc main thread, nơi đang phải gánh parse, compile, chạy JS. Trong profiler, bạn sẽ thấy:

  • Cảnh báo Partially Presented Frame hoặc Dropped Frame: trình duyệt muốn tạo frame nhưng không kịp.
  • Track Frames có một khoảng dài không có frame nào, thường trùng với các task JS lớn.

Mọi cập nhật giao diện phụ thuộc main thread đều chỉ tạo frame được khi main thread rảnh để chạy render steps. Animation phụ thuộc main thread thì frame rate của nó bị trói vào nhịp đó. May là trình duyệt có cách tăng tốc: đẩy animation sang compositor thread.

02 · KIỂM TRA

Cơ chế nào được compositor tăng tốc?

Animation đang giật thì câu trả lời thường là “không”. Bảng tham khảo (trình duyệt thay đổi liên tục; nghi ngờ thì ghi trace):

Thuộc tính ảnh hưởng layout

Animate thuộc tính cần thông tin chỉ main thread có (như Layout Tree) thì animation bị trói vào main thread. Ví dụ width, height, top, left, margin. Nên dùng transform và opacity.

/* ✗ bị main thread trói: width cần Layout */
.drawer { transition: width 300ms ease; }
.drawer.open { width: 320px; }

/* ✓ compositor xử lý được: transform không cần Layout */
.drawer { width: 320px; transform: translateX(-100%); transition: transform 300ms ease; }
.drawer.open { transform: translateX(0); }
03 · CƠ CHẾ

Compositor thread là gì

Compositor thread nằm trong chính renderer process của trang. Nó điều phối các thao tác đồ hoạ: nhận thông tin từ main thread và phối hợp với khâu raster, hiển thị (bài 27). Nhiều lập trình viên không biết nó tồn tại.

Khác main thread, compositor không chạy JavaScript, và không có API nào để gọi nó trực tiếp (như Web Worker). Cách duy nhất là khai báo animation đúng cách để trình duyệt tự giao cho nó. Khi đó animation tạo frame đều đặn, không bị gián đoạn bởi JS nặng. Điều này đặc biệt có giá trị trong những giai đoạn main thread bận nhất: React render phía client, parse/compile bundle lớn.

04 · BA VÍ DỤ

Cùng một spinner, ba cách viết

① requestAnimationFrame: phụ thuộc main thread

const spinner = document.querySelector('.spinner');
const PERIOD = 1500;  // một vòng mất 1,5 giây
function tick(now) {
  const deg = ((now % PERIOD) / PERIOD) * 360;
  spinner.style.transform = `rotate(${deg}deg)`;
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);

requestAnimationFrame cố chạy mỗi frame một lần nhưng cần JS, tức cần main thread. Main thread rảnh thì mượt; gặp long task thì không thể ra frame đúng nhịp, và spinner khựng lại.

② CSS animation: compositor lo

@keyframes spin { to { transform: rotate(360deg); } }
.spinner { animation: spin 1.5s linear infinite; }

Trình duyệt hiểu rằng phần tử có class này nên được animate trên compositor thread. JS nặng tới đâu thì spinner vẫn quay đều. Các cập nhật khác từ main thread (React render phần tử khác) vẫn tới compositor, nhưng không ảnh hưởng nhịp của animation này.

③ SVG animation: trông khai báo nhưng không được tăng tốc

<svg viewBox="0 0 100 100" width="80" height="80">
  <circle cx="50" cy="50" r="40" fill="none" stroke="teal" stroke-width="8" stroke-dasharray="180 80">
    <animateTransform attributeName="transform" type="rotate"
      from="0 50 50" to="360 50 50" dur="1.5s" repeatCount="indefinite" />
  </circle>
</svg>

Dù cú pháp là khai báo, <animateTransform> không báo cho trình duyệt chuyển animation sang compositor và vẫn dựa vào cấu trúc dữ liệu của main thread, giống ví dụ ①. Đây là bẫy hay gặp: designer xuất animation SVG từ công cụ thiết kế, nơi không có JS nặng chạy kèm, nên trông rất mượt. Đưa vào sản phẩm thật thì bỗng giật.

  • Animation giật = phụ thuộc main thread. Kiểm tra cảnh báo Dropped/Partially Presented Frame.
