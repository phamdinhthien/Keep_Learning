Minify CSS và JavaScript

Minifier làm hai việc: xoá code chắc chắn không chạy, rồi thu gọn phần còn lại. Hiểu nó để không vô tình phá tác dụng.

Bài gốc: “Reduce your resource size with CSS and JavaScript Minification” ↗
00 · MINIFIER LÀ GÌ

Công cụ build phân tích tĩnh để thu nhỏ file

Minify là kỹ thuật phổ biến nhất để giảm resource size (bài 15). Minifier đọc code JS/CSS mà không chạy nó, rồi:

  • Dead code elimination: tìm và xoá hẳn những đoạn chắc chắn không bao giờ chạy.
  • Renaming & reformatting: với phần còn lại, đổi tên biến cho ngắn một cách an toàn và bỏ khoảng trắng, định dạng thừa.

Dùng Webpack, Vite hay công cụ build phổ biến khác thì gần như chắc chắn bạn đã có minifier ở chế độ production.

Vì sao quan trọng: file lớn tốn cả thời gian truyền lẫn thời gian CPU. Không nên gửi tới người dùng bất kỳ byte nào thừa hay không dùng.

02 · DEAD CODE ELIMINATION

Xoá thứ chắc chắn không chạy

Với JS, minifier phân tích các nhánh để thấy nhánh nào không bao giờ tới được:

// trước
const DEBUG = false;
if (DEBUG) {
  showDebugPanel();
} else {
  startApp();
}

// sau: DEBUG luôn false nên chỉ còn
startApp();

Với CSS, minifier bỏ giá trị lặp thừa:

.card { margin: 12px 12px 12px 12px; }   /* trước */
.card { margin: 12px; }                    /* sau */

Tree shaking

Là một dạng dead code elimination dành riêng cho cú pháp import/export của ES modules. Công cụ phân tích đồ thị import để bỏ các export không ai dùng.

// utils.js
export function formatPrice(v) { return v.toLocaleString() + ' ₫'; }
export function slugify(s) { /* … */ }
export function deepClone(o) { /* … */ }

// app.js: chỉ dùng formatPrice → bundle cuối chỉ chứa formatPrice
import { formatPrice } from './utils.js';
Điều kiện để tree shaking chạy • Với Webpack, khai báo "sideEffects": false trong package.json (nếu module thật sự không có side effect).
• Dùng import/export của ES modules, không dùng require/module.exports của CommonJS.
• Với TypeScript, đặt module là es6/es2015 trở lên.
03 · RENAMING & REFORMATTING

Thu gọn phần còn lại

Phần code không xoá được thì được làm cho nhỏ nhất có thể, còn gọi là mangling hay compression:

// nguồn
export function rollDice() {
  const result = Math.floor(Math.random() * 6) + 1;
  return result;
}
rollDice();

// sau khi bundle + minify
function n(){return Math.floor(6*Math.random())+1}n();
  • Bỏ khoảng trắng và xuống dòng vốn chỉ để dễ đọc.
  • Đổi tên rollDice thành n.
  • Bỏ biến trung gian result vì bỏ đi không đổi logic.

Việc gộp các file theo đồ thị import là của bundler, không phải của minifier. Với CSS, lợi ích chủ yếu đến từ việc bỏ khoảng trắng: .title{font-size:18px}.

  • Minify = xoá code chết + thu gọn code sống.
  • Kiểm tra tree shaking thật sự hoạt động (ESM, sideEffects).
  • Chưa bật minifier thì bật ngay: tối ưu rẻ mà hiệu quả. Bài 25 cho thấy cách viết code cũng ảnh hưởng tới kết quả minify.
