Đọc flamegraph cơ bản

Chiều ngang là thời gian, chiều dọc là call stack. Ba ví dụ nhỏ là đủ để đọc được biểu đồ thật.

Bài gốc: “How to Read Flamegraphs” ↗
00 · KHÁI NIỆM

Call stack theo thời gian, vẽ thành hình

Flamegraph là cách tiêu chuẩn để vẽ call stack lúc chạy cùng thời gian của từng hàm, theo dạng phân cấp. Mục đích: giúp bạn tìm nhanh điểm nghẽn và những đường code chạy nhiều. Hai quy tắc đọc:

  • Chiều ngang là thời gian: khối càng rộng thì hàm càng tốn thời gian (tính cả các hàm nó gọi).
  • Chiều dọc là độ sâu call stack: hàm gọi nằm một tầng, hàm được gọi nằm tầng kế bên.
▣Ảnh/ví dụ gốc ảnh một flamegraph thật trong Chromium Profiler↗
01 · VÍ DỤ 1

Ba hàm gọi nối tiếp

function busy(ms) {                  // chặn luồng đúng ms mili-giây
  const t0 = performance.now();
  while (performance.now() - t0 < ms) {}
}
function parseRow()  { busy(40); }
function loadTable() { parseRow(); }
function init()      { loadTable(); }
init();
parseRow · 40 ms
loadTable · 40 ms
init · 40 ms
Flamegraph truyền thống: hàm đầu tiên ở đáy, “ngọn lửa” mọc lên trên

Cả ba khối rộng như nhau vì init và loadTable chỉ chờ parseRow làm việc.

03 · ICICLE GRAPH

Chromium vẽ lộn ngược

Các hình trên là flamegraph “truyền thống”, kiểu nhiều profiler dùng. Performance panel của Chromium vẽ một biến thể gọi là icicle graph (hình cột băng): cùng dữ liệu nhưng lật trục dọc. Hàm đầu tiên nằm trên cùng, hàm được gọi treo xuống dưới.

04 · TRÊN TRACE THẬT

Khối không đều tăm tắp, và điều đó không sao

Ghi trace đoạn code trên, bạn sẽ thấy một task JS khoảng 240 ms với call stack nông: (anonymous) → init → loadTable → parseRow. Nhưng các khối không đều 40 ms: profiler lấy mẫu call stack theo chu kỳ nên kích thước có xê dịch. Muốn số chính xác hơn, đặt thêm mốc performance.mark/measure (bài 12) để so trong track Timings.

Điều quan trọng là đọc được thời gian cộng dồn ở từng tầng, và thấy rằng parseRow, được gọi nhiều lần, là thứ duy nhất tạo ra toàn bộ thời gian của task.
