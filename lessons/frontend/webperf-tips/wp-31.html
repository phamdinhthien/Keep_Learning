Đo lúc component React thật sự hiện lên

React không render pixel, trình duyệt mới làm việc đó. Mark trong useEffect đến quá sớm; một hook nhỏ giúp đo đúng lúc frame xuất hiện.

Bài gốc: “Detecting when React Components are Visually Rendered as Pixels” ↗
00 · SỰ THẬT BẤT NGỜ

React không “render”

Dù API nổi tiếng nhất tên là render, React không vẽ gì lên màn hình. Việc hiển thị là của trình duyệt, do rendering pipeline viết bằng C++ điều phối. Việc của React là sửa DOM và style; như mọi công nghệ UI bằng JS khác, nó dựa vào engine của trình duyệt để định vị và vẽ.

Cần nắm mark/measure (bài 12), cách đo paint (bài 30) và event loop (bài 01). Điều quan trọng nhất: trình duyệt không thể hiển thị thay đổi nào đang được chuẩn bị trong JS cho tới khi task JS đó chạy xong.

React (task JS) sửa DOM + CSS→Trình duyệt: Style, Layout, Paint→Frame
01 · CÁCH ĐO NGÂY THƠ

Đặt mark trong useEffect

function OrderList({ orders }) {
  useEffect(() => {
    if (orders?.length) performance.mark('orders:rendered'); // ✗ quá sớm
  }, [orders]);

  return (
    <ul>
      {orders?.map(o => <li key={o.id}>{o.code} · {o.total}</li>)}
    </ul>
  );
}

Nhiều người cho rằng props/state đổi thì màn hình đổi ngay. Thực ra mark này ghi một thời điểm bên trong task JS mà React đang dùng để cập nhật DOM, còn khá lâu mới tới lúc có pixel:

  • React thường còn việc phải làm trước khi kết thúc task.
  • Trình duyệt phải chạy hết các microtask đang chờ, dù có liên quan tới cập nhật này hay không.
  • Có thể có task khác chen vào main thread trước khi frame được tạo.

02 · HOOK CHÍNH XÁC HƠN

Dùng lại kỹ thuật rAF + MessageChannel

function afterNextPaint(cb) {
  let cancelled = false;
  requestAnimationFrame(() => {
    const { port1, port2 } = new MessageChannel();
    port1.onmessage = () => { if (!cancelled) cb(); };
    port2.postMessage(null);
  });
  return () => { cancelled = true; };   // huỷ nếu component unmount
}

function useMarkAfterPaint(markName, ready) {
  useEffect(() => {
    if (!ready || document.visibilityState === 'hidden') return;  // tab ẩn: rAF không chạy
    return afterNextPaint(() => performance.mark(markName));
  }, [markName, ready]);
}

Dùng trong component, chỉ bật khi đã có dữ liệu thật để hiển thị:

function OrderList({ orders }) {
  useMarkAfterPaint('orders:painted', !!orders?.length);
  /* … JSX như trên … */
}

Khi orders có dữ liệu, hook xếp một performance.mark() chạy ngay sau frame đầu tiên được tạo sau task cập nhật của React. Bản production nên xử lý cả trường hợp tab ẩn và huỷ khi component unmount, như đoạn code trên đã làm.

03 · TRÊN TRACE THẬT

Hai mốc cách nhau thấy rõ

Trang demo của bài gốc có một nút: bấm vào thì tải JSON từ xa rồi cập nhật danh sách bằng React, kèm vài độ trễ giả lập cho giống ứng dụng thật (hiếm khi chỉ là một <ul> đơn giản). Trong trace:

  1. Fetch dữ liệu xong, React bắt đầu render.
  2. Mark kiểu ngây thơ được ghi, nhưng frame chưa lên màn hình.
  3. JS chạy xong, trình duyệt tạo frame (thấy trong track Frames).
  4. Ngay sau frame, mark của hook được ghi.
▣Ảnh/ví dụ gốc ảnh trang demo, trace với hai mốc và sơ đồ tương ứng↗
  • Vòng đời React (useEffect…) không phản ánh trải nghiệm thật của người dùng.
  • Người dùng quan tâm tới frame và pixel, nên số đo phải chạm tới đó.
  • Gói kỹ thuật đo paint vào một hook để dùng lại ở mọi component quan trọng.
