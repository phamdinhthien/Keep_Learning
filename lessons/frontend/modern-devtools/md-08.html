01. Bối cảnh 00:00–01:00

TodoMVC giới thiệu cách dựng cùng một app MVC bằng nhiều framework; bài dùng bản Vanilla JS với các todo đánh số 1–7

TodoMVC là dự án lớn với cùng một ứng dụng viết bằng nhiều framework: Vanilla, jQuery, React, Vue, Angular… để minh hoạ cách dựng một app MVC đơn giản. Thêm todo 1 đến 7, bật tắt trạng thái hoàn thành, xoá todo. Đánh số liên tiếp là cố ý: bug sẽ lộ rõ hơn. Người mới với JS hay xuất thân design vẫn theo được; phần CSS sẽ có ở các bài sau.

02. Tái hiện bug 01:00–02:00

Xoá todo 4 thì trên giao diện đúng; reload thì todo 4 hiện lại còn todo 1 mất; xoá 5 thì 5 quay lại, 2 mất

  1. Thêm vài todo.
  2. Xoá, ví dụ todo 4: trên màn hình biến mất đúng.
  3. Reload: todo 4 xuất hiện lại, todo 1 bị xoá.

Thử lại với todo 5: reload thì 5 quay lại, 2 biến mất. Đây là website "production grade" và bug đến từ báo cáo của người dùng. Bug được cố ý đưa vào một bản fork để luyện tập.

03. Bắt đầu từ trình duyệt 02:00–04:00

Đọc code trong editor không phải nguồn sự thật: trình duyệt có thể tải module khác, như node_modules/base.js bị editor ẩn; DevTools mới cho biết cái thật sự chạy

Một cách là mở code editor xem HTML và các file JS. Vấn đề: đó không phải source of truth, không đảm bảo là cái chạy trong trình duyệt. Trình duyệt có thể tải động module khác. HTML tham chiếu node_modules/…/base.js, nhưng Sublime Text được cấu hình ẩn thư mục node_modules, nên lướt thư mục JS sẽ bỏ sót. Network panel thì liệt kê đúng mọi JS được tải. Khi debug, hãy bắt đầu từ trình duyệt.

04. DOM breakpoint: debug từ ngoài vào trong 04:00–05:00

Chọn ul cha của các todo, Break on › subtree modifications; xoá một todo là dừng ngay ở dòng JS làm đổi DOM

Kỹ thuật debugging from the outside in: khi xoá todo thì giao diện đổi. Inspect một todo, chọn cha gần nhất là thẻ ul, chuột phải › Break on › subtree modifications: "khi bất kỳ phần tử con nào đổi, hãy dừng ở đúng dòng JS gây ra". Phần tử có chấm xanh báo đang có DOM breakpoint. Xoá todo 5: dừng ngay ở breakpoint. Chưa từng thấy app này, vài cú click đã tới dòng JS xoá phần tử. Cũng áp dụng cho thêm hay sửa phần tử.

05. Sources panel 05:00–06:30

Sources gồm nhiều pane: navigator, code editor, call stack và scope; scope cho biết biến nào truy cập được ở dòng đang dừng

Lần đầu thấy Sources panel: một panel chia nhiều pane. Pane sources/navigator liệt kê file app đã tải; file mở ra ở code editor (thường dùng để xem hơn là sửa); chuột phải tab › Close All. Nửa dưới: call stack và scope. Đang dừng ở dòng 34, scope cho thấy truy cập được elem, id và this.

Phần tử vẫn biến mất khỏi view; lỗi là nó không bị xoá ở "server", ở đây là local storage. TodoMVC = Model View Controller: view là cái thấy, model không chạm database mà chạm local storage.

06. Đi qua call stack 06:30–09:40

Call stack là chuỗi lời gọi dẫn tới điểm dừng; đi từng mục, nhìn tên hàm: view._removeItem, render, xử lý event, rồi tới Model.remove và Store.remove

Call stack biểu diễn mọi lời gọi hàm trước điểm dừng: View._removeItem được gọi bởi removeItem, rồi View.render, một hàm ẩn danh… Bấm từng mục là nhảy tới code của nó. Cách làm "không khoa học": đi từng cái một và cố hiểu code; ẩn navigator cho rộng chỗ.

dispatchEvent, $delegate: lo event delegation, bỏ qua. Hàm ẩn danh xử lý itemRemove, destroy, click. Thấy tên như removeItem là dấu hiệu đúng hướng (không phải itemToggle hay itemEditCancel). Rồi tới Model.remove: đi từ view qua controller tới model. Đến Store.remove thì có nhiều logic hơn hẳn: vòng for, if, thao tác mảng. Đây là ứng viên tốt để debug.

07. Kiểm tra ID 09:40–11:00

Ở Model.remove, giá trị id hiện ngay trong scope; Cmd + F trong Elements tìm id đó thấy đúng todo 4, nên mọi thứ trước đó ổn

Quay lại Model.remove: có tham số id cần xoá. Hover để xem giá trị (hoặc chuột phải › copy), tiện hơn nữa là nó hiện sẵn trong scope pane. Giả định id nằm trong DOM: vào Elements, Cmd + F, dán id, tìm ra đúng todo 4. Vậy các lời gọi tới đây đều đúng; bug nằm phía trên.

08. Tìm bug trong Store.remove 11:00–15:00

Đặt breakpoint, reload, xoá lại; Continue to here tới dòng splice thấy i = 0, vô lý; dòng trên xoá todo đầu tiên KHÁC id cần xoá

Thói quen của tác giả: khi muốn hiểu kỹ một hàm, đặt breakpoint ở đó, resume, reload trang, làm lại từ đầu. Đi qua lại call stack lâu đôi khi làm DevTools rối. Đặt breakpoint trong remove của store.js, xoá todo 4.

Đọc to code: lấy danh sách todo từ local storage, gán vào todos, lặp qua từng todo, so sánh với id, xoá khỏi mảng, break, stringify và ghi lại local storage, gọi callback. Dòng xoá thật sự (splice, dòng 118) có vẻ là nơi hỏng. Chuột phải › Continue to here để dừng ở dòng 118. Gõ i vào console: 0. Vô lý: đang xoá todo 4 chứ không phải phần tử đầu.

Bug nằm ở dòng trên: "nếu todo đang duyệt khác id cần xoá thì xoá nó". Nhờ break, nó xoá todo đầu tiên không trùng id. !== phải là ===. Ghi chú khoá học gợi ý: dòng 117 của store.js.

09. Sửa trực tiếp khi đang dừng 15:00–16:20

Chuột phải Store.remove › Restart frame để quay về dòng đầu hàm, sửa !== thành ===, Cmd + S để nạp lại vào V8, resume và reload để kiểm tra

Đang dừng ở dòng sau dòng cần sửa, nên chuột phải Store.remove trong call stack › Restart frame: nhảy về dòng đầu của hàm. Sửa điều kiện thành bằng, nhấn Cmd + S: có một chớp nhỏ và breakpoint dừng lại, đó là DevTools re-inject code vào V8. Resume: todo 4 biến mất; reload: todo 4 không quay lại, todo 2 vẫn còn. Thay đổi không được lưu vào file vì chưa cấu hình DevTools làm việc đó.

10. Tóm tắt 16:20–18:40

DOM breakpoint đưa tới dòng gây đổi DOM, đi qua call stack theo tên hàm, đoán chỗ có logic, step qua, sửa và lưu; rồi mới sửa file thật trong editor

  • Không đọc code trước, mà dùng DOM breakpoint để debug từ ngoài vào.
  • Đi qua call stack một cách hệ thống; ghi chú tên hàm vì đó là gợi ý tốt nhất.
  • Giả định bug nằm ở chỗ có logic, step qua, sửa, Cmd + S để nạp lại.
  • Cuối cùng mở Sublime, Ctrl + G tới dòng 117 và sửa thành === trong file thật. Xoá todo 5, nó không quay lại.

Quy trình live debug: dừng ở breakpoint › sửa code › lưu › resume.
