Modern DevTools · Lesson 6

Debug module clipboard của Node.js: tìm đường dẫn, chạy với --inspect --debug-brk, rồi sửa code ngay khi đang dừng

Một bài ngắn tạm rời chủ đề hiệu năng: mở DevTools riêng cho Node.js, chạy thử biểu thức trong console và live-edit để thêm tiền tố vào output.
Terminal — zsh
$ node clipboard
Error: Cannot find module '/Users/user/clipboard'
 
$ which clipboard
/Users/user/.nvm/versions/node/v7.8.0/bin/clipboard
 
$ node --inspect /Users/user/.nvm/versions/node/v7.8.0/bin/clipboard
Debugger listening on port 9229. … (chạy xong, thoát ngay)
 
$ node --inspect --debug-brk /Users/user/.nvm/versions/node/v7.8.0/bin/clipboard
Debugger listening on port 9229.
To start debugging, open the following URL in Chrome: … ← chờ, không thoát

01. Bối cảnh 00:00–01:50

Module clipboard in ra nội dung clipboard; tác giả tưởng nó có bug, hoá ra do lỡ bôi đen trong iTerm, và muốn thêm tiền tố cho output rõ hơn

Sau hơn một giờ nội dung về hiệu năng ở các bài trước, bài này nghỉ một chút để xem Node debugging. Module clipboard (cài global) chỉ làm một việc: in ra nội dung clipboard. Tác giả từng thấy nó in ra thư mục hiện tại và tưởng module có bug. Thực ra trong iTerm, bôi đen chữ là chữ đó vào clipboard, nên lỗi là do người dùng.

Module có phạm vi hẹp như vậy là tốt. Nhưng để học, đặt mục tiêu: sửa module để output có tiền tố kiểu “Your clipboard contents”, và làm điều đó bằng debugging.

Lưu ý: Node.js trong video là bản 7.8.0. Ghi chú khoá học nói thêm: Node.js hiện đại có sẵn tích hợp V8 Inspector, nên DevTools debug được code Node.
02. Tìm đường dẫn 01:50–02:40

“node clipboard” lỗi vì Node tìm file tên clipboard trong thư mục hiện tại; dùng which clipboard để lấy đường dẫn đầy đủ

Chạy node clipboard không được: Node tìm một file tên clipboard ở thư mục đang đứng. Với binary cài global, dùng which clipboard để lấy full path, nằm trong thư mục bin của phiên bản Node (nơi mọi module global sống). Sau đó có thể cd vào đó, hoặc dán nguyên đường dẫn vào lệnh.

▸ Ví dụ của nguồn
$ which clipboard
/Users/user/.nvm/versions/node/v7.8.0/bin/clipboard
03. Cờ --inspect và --debug-brk 02:40–04:00

Chỉ --inspect thì chương trình chạy xong trước khi kịp mở URL debug; thêm --debug-brk để Node dừng ở dòng code đầu tiên

node --inspect clipboard mở một phiên debug và in ra URL để dán vào trình duyệt. Nhưng module chạy quá nhanh: in xong clipboard là thoát, mở URL chỉ thấy "connection was closed". Thêm --debug-brk sau --inspect: đây là chỉ dẫn cho Node "tôi muốn dùng debugger của DevTools, hãy đặt breakpoint ở dòng đầu tiên". Giờ lệnh không kết thúc mà chờ.

04. Mở DevTools riêng cho Node 04:00–04:20

Khi có phiên debug, logo Node trên thanh DevTools chuyển xanh; bấm vào để mở một DevTools riêng cho Node.js, hoặc vào chrome://inspect

Có thể copy URL, nhưng có cách tốt hơn: trong Chrome, mục Open dedicated DevTools for Node.js (logo Node) chuyển xanh khi có phiên debug đang chạy; dừng lệnh thì nó xám lại. Bấm vào là được một DevTools riêng cho Node.js, đang dừng bên trong chương trình. Cách khác: vào chrome://inspect/.

05. Evaluate in console & Continue to here 04:20–05:30

Bôi đen biểu thức rồi Evaluate in console để chạy thử; báo “clipboard is not defined” vì require nằm sau breakpoint, nên Continue to here trước

Trước khi sửa, kiểm tra thứ đang được log đúng là nội dung clipboard. Bôi đen biểu thức, chuột phải, chọn Evaluate in console: chạy riêng đoạn JS đã chọn trong console. Lần đầu báo clipboard is not defined, hợp lý vì lệnh require nằm sau dòng đang dừng.

Sửa bằng chuột phải tại dòng cần tới, chọn Continue to here. Giờ clipboard đã có giá trị (thấy qua inline variable values hiện ngay cạnh code). Vào console, nhấn mũi tên lên để gọi lại lệnh cũ, Enter: kết quả đúng là đoạn chữ vừa copy.

06. Live edit JavaScript 05:30–06:20

Khi đang dừng, code trong Sources sửa được; thêm chuỗi tiền tố, Cmd + S để DevTools nạp lại vào V8, rồi resume để thấy output mới

Bấm vào code thấy con trỏ nhấp nháy: cả file sửa được. Live editing JavaScript là một trong những tính năng ít người biết của DevTools. Thêm chuỗi "Your clipboard contents" cùng một dòng mới vào console.log, ngăn bằng dấu phẩy, rồi save. Chỉ việc lưu đã đủ để DevTools re-inject JS đã sửa vào engine V8. Bấm resume script execution: thông điệp đã đổi, cả trong console của DevTools lẫn trong terminal.

▸ Minh hoạ — sửa dòng log như trong video
// trước
console.log(content);
// sau khi live edit + Cmd/Ctrl + S
console.log('Your clipboard contents:\n', content);
07. Tóm tắt & thử thách 06:20–07:50

Nhớ: which để lấy đường dẫn, --inspect --debug-brk (hoặc --inspect-brk), logo Node xanh; thử lại với cowsay

  • Binary cài global: dùng which để lấy đường dẫn đầy đủ.
  • Đừng quên --inspect cùng --debug-brk; bản Node mới dùng --inspect-brk.
  • Logo Node trong DevTools xanh lên khi có phiên debug; với code thật bạn sẽ thấy source dừng ở dòng đầu.
  • Có thể live-edit JS khi đang dừng ở breakpoint.
▸ Thử thách của nguồn
npm i -g cowsay
cowsay hello
node --inspect-brk $(which cowsay) hello
