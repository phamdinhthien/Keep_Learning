Abstraction là “What”, Encapsulation là “Group”

Cả hai đều ẩn giấu thông tin nên dễ nhầm. Abstraction lược bỏ chi tiết để tinh giản cấu trúc; Encapsulation gom data + code vào một unit để bảo vệ state bên trong.
Abstraction đưa ra mặt tiền ở mức What · Encapsulation gom và giấu phần How
01. Bản chất: What vs Group

Cùng để ẩn giấu thông tin, khác nhau ở mục tiêu

Hai kỹ thuật đều phục vụ information hiding trong OOP, nên dev hay lẫn khi phân định. Muốn phân biệt thì xem mỗi cái nhắm vào mục tiêu nào.

ABSTRACTION · WHAT

Mô tả hành vi, bỏ qua chi tiết
  • Phục vụ thiết kế cấu trúc, kiến trúc phần mềm.
  • Lược bỏ phần detailing mà hệ thống chưa cần, chưa muốn hoặc chưa biết cách làm cụ thể.
  • Ví dụ: Animal.eat() mô tả hành vi ăn khi chưa có chi tiết triển khai.

ENCAPSULATION · GROUP

data + code → single unit
  • Gom data và code vào một unit duy nhất.
  • Mục đích: bảo vệ dữ liệu khỏi tác động trực tiếp từ bên ngoài.
  • Nếu viết eat() trong class thường, method buộc phải có body cụ thể hoặc để rỗng.
Ví dụ Animal.eat() — hai cách viết
// Abstraction: định nghĩa hành vi, chưa cần chi tiết abstract class Animal { abstract eat(); } // Class thường: buộc phải có body (hoặc để rỗng) class Animal { eat() { /* ??? */ } }
02. Cơ chế Encapsulation

Từ biến rời rạc đến object Book

Lập trình thủ tục khai báo dữ liệu bằng các biến lẻ, ví dụ ID và name nằm ở hai mảng riêng. Gom chúng vào một object Book thì thao tác và quản lý dễ hơn.

TRƯỚC · THỦ TỤC

Biến rời rạc

ids[], names[] là hai mảng riêng, validate để ở library hoặc rải rác nơi dùng.

SAU · OOP

Object Book

id, name và validate() nằm trong cùng một class.

Hai lợi ích của việc gom nhóm
1
Gắn data với logic nghiệp vụ: validate() đặt ngay trong Book. Nơi nào cần kiểm tra chỉ việc gọi method của object, nên tái sử dụng được và dữ liệu được bảo vệ.
2
Kiểm soát phạm vi truy cập bằng private / public / internal hoặc Getter/Setter (read-only, write). Bạn quyết định phần nào bộc lộ ra ngoài, phần nào ẩn đi.

Chỉ chính object được thay đổi state của nó

Code bên ngoài không can thiệp trực tiếp vào property, chỉ tác động qua những method mà object cho phép gọi. Ví dụ: tuổi của một người tăng sau một năm.

Bên ngoài chỉ gọi method · việc cập nhật tuổi nằm trong object

06. Bao đóng tham số: Login Data

Encapsulation áp dụng ngay khi thiết kế tham số function

So sánh hai cách truyền tham số cho hàm login.

CÁCH 1 · THAM SỐ RỜI RẠC

login(username, password) login(email, password) ? login(phone, otp) ?
  • Hàm nhận từng tham số riêng như username, password.
  • Thêm kiểu login email/password hay phone/OTP thì phải sửa danh sách tham số hoặc copy function.

CÁCH 2 · GOM THÀNH LOGIN DATA

login(data: LoginData) { data.validate() // throw nếu sai ... }
  • Gom username, password hoặc thông tin đăng nhập khác vào một data object.
  • Logic kiểm tra nằm trong object: validate() throw lỗi khi dữ liệu không hợp lệ.
  • login gọn hơn vì không phải gọi library bên ngoài để kiểm tra từng trường.
Lợi ích tổng thể
✓
Class dễ sửa đổi và dễ maintain hơn.
✓
Giảm độ phức tạp cho người dùng (người dùng SDK là các dev trong công ty).
✓
Giảm code lặp lại, dễ mở rộng và tái sử dụng tốt hơn.

Theo mentor, dev có thể vẫn hiểu sai hai khái niệm dù đã dùng interface hoặc abstract class khi code.
