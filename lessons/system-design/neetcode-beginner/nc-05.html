DNS là cuốn danh bạ của internet: đổi domain name thành IP để client biết gửi request tới đâu

DNS là một hệ thống rất lớn và phi tập trung. Bài này đơn giản hoá, nhưng vẫn đi sâu hơn mức cần cho phỏng vấn.

01. Vì sao cần DNS ~00:00–02:00

Không ai muốn nhớ IP của google.com — ta cần một tên thân thiện trỏ tới IP, như danh bạ trỏ tên tới số điện thoại

Client muốn vào google.com thì phải gửi request tới server của Google, mà server có một IP address. Chẳng lẽ ai cũng phải gõ con số đó vào trình duyệt? Giống danh bạ điện thoại, hay danh sách contact trong điện thoại: tên mỗi người trỏ tới số của họ. Domain name cũng vậy: một tên thân thiện trỏ tới IP của server.

Ngắn gọn: muốn vào google.com, ta hỏi domain name system (DNS) IP của google.com là gì; DNS trả về IP; ta biết chính xác gửi request tới đâu và nhận response. Đa số developer chỉ cần biết tới đây, phỏng vấn system design cũng vậy.

▸ Ví dụ của nguồn — danh bạ
Danh bạ điện thoạiTên người → số điện thoại.
DNSgoogle.com → IP của server Google.
02. Demo nslookup ~02:00–03:30

Gõ domain hay gõ thẳng IP thì cũng tới cùng một trang, vì máy tính đã dịch domain sang IP

Vào google.com và nhấn Enter là tới trang Google: máy tính đã dịch domain sang IP. Lệnh shell nslookup cho thấy điều đó: nó trả về IP của google.com. Dán IP này vào trình duyệt cũng về đúng google.com, vì IP đó thuộc về Google.

▸ Ví dụ của nguồn — demo trong video
$ nslookup google.com
Name:    google.com
Address: <IP của Google>   // copy IP này
// dán IP vào thanh địa chỉ → vẫn mở ra google.com

Định dạng output là minh hoạ; video không đọc to địa chỉ IP cụ thể.

03. ICANN, registrar & DNS record ~03:30–07:30

ICANN quản lý mọi domain, registrar bán lại domain và giữ DNS record; A record nối domain với IP

Phía sau có nhiều thành phần. Internet service provider (ISP) là mắt xích quan trọng: không có internet thì không có gì chạy, và ISP là bên nói chuyện với các server DNS. Rồi tới ICANN (Internet Corporation for Assigned Names and Numbers): về cơ bản là chủ của mọi domain trên thế giới. Vì sao chỉ một người sở hữu google.com, sao tôi không "cướp" được? Vì mọi thứ đi qua ICANN.

ICANN là tổ chức phi lợi nhuận nên không trực tiếp bán domain. Các đơn vị bán lại được công nhận gọi là domain registrar: Google Domains, Namecheap, GoDaddy… Mua domain là phải qua một registrar. Request đi qua ISP, qua các server của ICANN — những server này biết domain nào thuộc registrar nào (ví dụ neetcode.io qua Google Domains) — rồi tới server của registrar giữ DNS record.

DNS record lưu thông tin để resolve một truy vấn DNS. Có nhiều loại; một loại là A record (address record): domain trỏ tới một IP, mọi request tới domain được chuyển tới IP đó.

Hình 2 — Chuỗi truy vấn rút gọn: ISP → ICANN → registrar giữ A record
▸ Ví dụ của nguồn — A record của neetcode.io
; A record người nói cấu hình ở Google Domains
neetcode.io   A   <IP server của NeetCode>

Mọi request tới neetcode.io đi tới IP này, chính là server của người nói.

04. Cache IP ~07:30–08:30

IP của server ít khi đổi, nên client cache lại và không phải hỏi DNS mỗi lần

IP của server thường là static IP, dù không bắt buộc nhờ dynamic DNS (ngoài phạm vi khóa). Vì IP ít khi đổi, client cache IP: lần đầu vào neetcode.io sẽ có IP, IP được lưu trên máy (người nói cho là ở đâu đó trên disk). Lần sau không cần đi lại chuỗi truy vấn DNS. Đây là một ví dụ của caching.

▸ Ví dụ của nguồn — vào neetcode.io lần hai
Lần đầuĐi hết chuỗi DNS để lấy IP, rồi lưu lại.
Lần sauIP đã có trên máy, gửi request thẳng tới server.
05. Server là gì ~08:30–09:30

Server là một máy có public IP, thường gắn domain, và firewall cho phép traffic từ ngoài vào

Tóm lại vài bài vừa qua: server về cơ bản là máy tính có public IP, IP đó thường gắn với một domain name, và firewall của server được cấu hình cho phép traffic từ bên ngoài. Router nhà ta cũng có public IP, nhưng ta không muốn người ngoài gửi request vào máy mình, nên firewall chặn. Server thì nhận request, xử lý và trả response phù hợp.

▸ Ví dụ của nguồn — router nhà và server công khai
Router nhàCó public IP, firewall chặn request từ ngoài.
Server công khaiCó public IP, firewall cho phép request tới server.
06. Cấu trúc URL ~09:30–13:00

URL gồm protocol, subdomain, domain name, TLD và path; mua domain là sở hữu phần domain và mọi subdomain của nó

Protocol đứng đầu: trên trình duyệt chủ yếu là HTTP hoặc HTTPS, nhưng có giao thức khác, ví dụ mở file trên máy (trên Windows sẽ trỏ tới ổ C). Phần protocol không thuộc domain. Đuôi .com là top-level domain (TLD); có .io như neetcode.io, mã quốc gia như .jp cho Nhật; TLD cũng do ICANN quản lý.

Mua google.com thì bạn sở hữu google.com: phần này là domain name hay primary domain. Phía trước là subdomain, không bắt buộc: domains.google.com là dịch vụ mua domain của Google. www cũng là subdomain, không có mục đích kỹ thuật, chỉ là quy ước từng rất phổ biến; gõ www.google.com sẽ bị chuyển về google.com. Cuối cùng là path, sau dấu "/", có thể có query params; path không thuộc domain.

Hình 3 — Các phần của URL; phần xanh lá là thứ bạn sở hữu khi mua domain

Sở hữu domain thì bạn kiểm soát nó và thêm bao nhiêu subdomain tuỳ ý. Bạn sẽ thêm một DNS record, nhiều khả năng là A record, nói "google.com trỏ tới IP server của tôi". Đó là cách "danh bạ" DNS hoạt động; nó rất phức tạp nhưng phỏng vấn không cần chi tiết.

▸ Ví dụ của nguồn — các URL trong video
  • google.com → không subdomain.
  • domains.google.com → subdomain "domains" của Google Domains.
  • www.google.com → bị chuyển về google.com.
  • neetcode.io → TLD là .io.

Năm câu hỏi

DNS giải quyết vấn đề gì?

Đổi tên thân thiện (domain) thành IP của server, như danh bạ đổi tên thành số điện thoại. (→ 01)

Lệnh nào xem IP của một domain?

nslookup, ví dụ nslookup google.com. (→ 02)

A record là gì, nằm ở đâu?

Address record: domain trỏ tới một IP. Nằm trên server của registrar (ví dụ Google Domains), cuối chuỗi truy vấn DNS. (→ 03)

Ba điều kiện để một máy là server công khai?

Có public IP, thường gắn domain name, và firewall cho phép traffic từ ngoài vào. (→ 05)

Trong https://domains.google.com/path, chỉ ra protocol, subdomain, domain name, TLD, path.

https · domains · google · .com · /path. (→ 06)
