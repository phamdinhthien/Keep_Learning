NeetCode · System Design Beginner · Video 18

Object storage lưu file lớn phẳng như một hashmap, đọc ghi qua HTTP — và không sửa được file đã lưu

Gần với file system hơn là database. Trong phỏng vấn, hễ có file lớn thì gần như luôn dùng object storage.

01. Phẳng, không có thư mục ~00:00–02:00

Object storage lưu dữ liệu phẳng, không có cây thư mục; "thư mục" trên S3 chỉ là một phần của tên file

Object storage trở nên quan trọng trong 10 hay 15 năm gần đây, mới hơn file system nhiều. Nó gần với file system hơn là database — với database, cách cấu trúc, lọc và tìm dữ liệu quan trọng hơn nhiều. Object storage lưu dữ liệu phẳng, không phân cấp: file system có folder lồng folder, còn object storage không có gì giống folder.

Ví dụ phổ biến: AWS S3, Google Cloud Storage; Azure cũng có dịch vụ riêng. Một số dịch vụ tạo ảo giác file system: trên S3 có "folder" chứa file, nhưng folder chỉ là một phần trong tên file. Mọi object trong S3 đều được lưu phẳng.

▸ Ví dụ của nguồn — "folder" trên S3
videos/2024/talk.mp4   // "videos/2024/" chỉ là phần tên, không phải thư mục thật

Tên file là minh hoạ thêm.

02. Blob ~02:00–04:00

Object là blob — binary large object: ảnh, video, bản backup database; ghi rồi đọc, nhưng không cập nhật

Tiền thân của object storage là blob storage; nói object là nói blob. Blob là binary large object (phần "ob" là object). Thường là media như ảnh, video, hoặc thứ lớn không phải media như bản backup database. Không phải loại file văn bản ta định sửa thường xuyên.

Đưa file vào object storage thì ghi được, đọc được, nhưng không sửa, không cập nhật được. Đó là một trade-off của object storage.

▸ Ví dụ của nguồn — hợp và không hợp
HợpẢnh, video, bản backup database.
Không hợpFile văn bản thường xuyên cần chỉnh sửa.
03. Giống một hashmap ~04:00–05:00

Mỗi object có key duy nhất nên truy cập rất nhanh; trên S3, tên phải duy nhất trên toàn cầu

Object storage được tối ưu để lưu rất nhiều object phẳng, nên tìm ngay được object đã lưu — như hashmap: mỗi object có key duy nhất, truy cập rất nhanh. Một điểm giống nữa: hashmap không có key trùng, blob storage và object storage cũng vậy. Với S3, tên phải duy nhất toàn cầu: không chỉ duy nhất trong các instance S3 của bạn, mà trùng tên với bất kỳ ai dùng S3 cũng không được.

Trên S3 thực tế, yêu cầu duy nhất toàn cầu áp dụng cho tên bucket; key của object chỉ cần duy nhất trong bucket. Video nói chung là "tên"; ghi chú này làm rõ thêm.
▸ Ví dụ của nguồn — hai điểm giống hashmap
  • Key duy nhất → truy cập object rất nhanh, không phải duyệt cây thư mục.
  • Không có trùng lặp → trùng tên với người khác trên S3 cũng không được.
04. Khi nào dùng ~05:00–08:00

File lớn (ảnh, video, lưu trữ dài hạn) để trong object storage, chỉ metadata để trong database; đọc file bằng một HTTP request

Về thiết kế, chỉ cần biết: lưu file lớn cho ứng dụng — ảnh, video, media — hay bất cứ thứ gì lưu dài hạn, thì dùng object storage. Có thể để ảnh và video trong database, nhưng chẳng hợp lý: có bao giờ query theo nội dung ảnh hay video? Metadata — tên ảnh, tag, tên hay tiêu đề video — thì để trong database. Còn video có thể tới hàng gigabyte: để trong database làm chậm query, tăng dung lượng, đọc ghi database liên tục, và user muốn xem thì ứng dụng phải đọc từ database rồi mới gửi đi.

Giao diện đọc ghi object storage là HTTP: không query, không viết SQL, không lọc, không đọc cả kho. Chỉ cần gửi một network request tới S3, hỏi theo tên file (duy nhất toàn cầu), cấu hình để chỉ mình truy cập được (bảo mật không đi sâu). Nhận video hay ảnh qua HTTP rồi gửi cho user. Chưa dùng S3 bao giờ thì hình dung giống Google Drive hay Dropbox: một đống file và ảnh, có ảo giác folder, nhưng không phải tìm trong cây — biết tên file là dùng được như key của hashmap.

Hình 2 — Metadata trong database, file trong object storage
▸ Ví dụ của nguồn — xem một video
// 1. lấy metadata (title, tag, tên file) từ database
// 2. lấy chính video bằng HTTP theo tên file

Dạng URL và tên file là minh hoạ thêm; nguồn chỉ nói "gửi network request tới S3 theo tên file".

Bốn câu hỏi

Blob là viết tắt của gì?

Binary large object. (→ 02)

Object storage giống hashmap ở hai điểm nào?

Mỗi object có key duy nhất để truy cập nhanh, và không có trùng lặp. (→ 03)

Bạn thiết kế app chia sẻ video. Lưu gì ở đâu?

Metadata (title, tag, tên file) trong database; file video trong object storage như S3, đọc qua HTTP. (→ 04)

Vì sao để video trong database là tệ?

Video có thể tới hàng GB: làm chậm query, tăng dung lượng, đọc ghi database liên tục, và phải đi qua ứng dụng để gửi cho user. (→ 04)
