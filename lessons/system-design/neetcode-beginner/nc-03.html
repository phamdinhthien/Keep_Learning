01. IP address ~00:00–03:30

Mỗi máy trên internet cần một public IP address để được nhận diện duy nhất, giống địa chỉ nhà khi gửi thư

Client muốn nói chuyện với server, giống gửi thư giữa hai ngôi nhà: phải biết địa chỉ mỗi nhà. Mọi máy giao tiếp qua public internet cần một public IP address. IP address nhận diện duy nhất một máy, nên server biết gửi dữ liệu cho client nào trong rất nhiều client.

IP address là một số nguyên 32 bit, thường viết thành bốn nhóm số ngăn bằng dấu chấm. Vì chỉ có 32 bit, mỗi nhóm không thể lên tới 999. Tổng cộng chỉ chứa được khoảng 4 tỉ public IP, ít hơn số người và số máy trên trái đất. Giới hạn 32 bit này là của IPv4; IPv6 mới hơn cho phép 128 bit, gần như không bao giờ chạm trần. IPv4 vẫn được dùng rất phổ biến.

Hình 2 — Bốn nhóm 8 bit ghép thành 32 bit
Đính chính nguồn: video nói mỗi nhóm tối đa "256" và "12 chữ số". Thực tế mỗi nhóm là 8 bit nên nhận giá trị 0–255 (256 giá trị), và nhóm có thể có 1–3 chữ số. Tổng 232 ≈ 4,3 tỉ địa chỉ.
▸ Ví dụ của nguồn — gửi thư

Phong bì ghi người gửi và người nhận kèm địa chỉ. Máy tính cũng vậy: dữ liệu gửi đi phải ghi IP đích và IP nguồn.

02. Packet & IP header ~03:30–06:00

Dữ liệu đi theo từng packet; phần header của packet là metadata, như mặt sau phong bì

Quy tắc gửi dữ liệu qua internet gọi là internet protocol (IP), nên địa chỉ mới gọi là IP address. Mỗi lần gửi là một packet. Một phần packet dành cho metadata mô tả cả packet, giống thông tin người gửi, người nhận ghi ngoài phong bì; trong máy tính phần này gọi là header.

IP header chứa source IP và destination IP, cùng vài thứ khác — đi sâu hơn là việc của một lớp học networking, không cần cho system design. Phần còn lại của packet là dữ liệu, như lá thư bên trong phong bì.

▸ Ví dụ của nguồn — phong bì và packet
Phong bìMặt ngoài: từ ai, gửi ai (metadata). Bên trong: lá thư.
IP packetIP header: source IP, destination IP. Phần còn lại: dữ liệu.
03. TCP ~06:00–09:00

Dữ liệu lớn phải chia thành nhiều packet; TCP header mang sequence number để bên nhận ráp lại đúng thứ tự

IP gửi được dữ liệu giữa hai máy nhưng chưa làm hết việc. Muốn gửi cả cuốn sách bằng phong bì (không dùng thùng carton), ta xé từng trang, chia vào khoảng 10 phong bì. Bên nhận có đủ trang, nhưng ráp lại thế nào nếu trang không đánh số? IP không có khái niệm này.

TCP (transmission control protocol) giải quyết vấn đề đó và nhiều vấn đề khác. Nhìn từ IP, một packet = IP header + dữ liệu. Khi dùng TCP, phần dữ liệu đó lại chia làm hai: TCP header và phần còn lại. TCP header có thứ IP header không có, ví dụ sequence number: server nhận đủ packet rồi ráp lại đúng thứ tự, như đánh số trang sách.

Hình 3 — Ví dụ cuốn sách: 10 phong bì tới nơi lộn xộn, sequence number giúp ráp lại
▸ Ví dụ của nguồn — gửi cả cuốn sách

Sách được chia vào 10 phong bì gửi từ một người tới một người khác. Có đánh số trang (sequence number) thì người nhận xếp lại được đúng thứ tự. Thứ tự lộn xộn trong hình là minh hoạ thêm.

04. Ba tầng giao thức ~09:00–11:00

Một request dùng cùng lúc IP, TCP và HTTP vì mỗi giao thức sống ở một tầng khác nhau

Phần dữ liệu thật mới là thứ kỹ sư phần mềm phải lo; IP và TCP ta coi như có sẵn. Đó là application data, ví dụ một HTTP request — giao thức ứng dụng phổ biến nhất. Dữ liệu HTTP của request hoặc response nằm ở phần này của packet và được ráp lại ở server để ứng dụng đọc.

Ba giao thức chạy cùng lúc vì ở ba tầng: HTTP ở application layer; TCP ở transport layer, bảo đảm dữ liệu tới nơi và ráp đúng thứ tự; IP ở network layer, lo việc tới đúng thiết bị, đúng máy.

Hình 4 — Ba tầng: application, transport, network
▸ Ví dụ của nguồn — một HTTP request

Trình duyệt gửi một HTTP request: IP đưa packet tới máy server, TCP ráp các packet đúng thứ tự, còn ứng dụng chỉ thấy nội dung HTTP request.

05. Public & private IP ~11:00–12:30

Server cần public IP; các thiết bị sau một router chỉ cần private IP trong LAN

Server muốn ai cũng truy cập được thì phải có public IP. Máy client thì không cần, vì không ai gửi request tới nó. Lưu lượng của client đi qua router: nhiều thiết bị nối vào một router thì chỉ router cần public IP. Trong mạng nội bộ — LAN (local area network) — router cấp cho mỗi máy một private IP.

Private IP không truy cập được từ internet công cộng. Các máy trong cùng LAN về kỹ thuật nói chuyện được với nhau, nhưng chạy server ở máy này rồi gọi bằng private IP từ máy kia còn dính tới firewall, port forwarding… nằm ngoài phạm vi khóa học.

Hình 5 — Router giữ public IP, các thiết bị trong LAN dùng private IP
▸ Ví dụ của nguồn — nhiều thiết bị, một router

Nhà bạn có nhiều thiết bị cùng nối một router: chỉ router có public IP; mỗi thiết bị nhận một private IP trong LAN. Các thiết bị cụ thể trong hình là minh hoạ thêm.

06. Static & dynamic IP ~12:30–13:30

Server nên có IP cố định để client luôn tìm thấy; IP của client thì thay đổi theo thời gian cũng không sao

Static IP là IP không đổi, quan trọng ở phía server: client gọi tới một IP, nếu server bỗng đổi IP thì rất phiền. Nhưng server cũng có thể dùng dynamic IP mà vẫn chạy được, nhờ dynamic DNS (ngoài phạm vi khóa). Client thường không cần static IP; nhiều khả năng mạng nhà bạn không có static IP và IP thay đổi theo thời gian, nhưng mọi thứ vẫn chạy bình thường.

▸ Ví dụ của nguồn — server đổi IP
Không có gì hỗ trợServer đổi IP, client vẫn gọi IP cũ → không tới được.
Có dynamic DNSServer dùng dynamic IP mà client vẫn tìm được.
07. Port ~13:30–17:00

Port là kênh giao tiếp trên một máy: mỗi port chỉ một ứng dụng dùng tại một thời điểm

Máy giao tiếp qua IP, đồng thời qua một port cụ thể, ví dụ 80, 22 hay 443. Port là giá trị 16 bit, nên mỗi máy có khoảng 65.000 port, quá đủ vì hiếm khi mở nhiều kênh hơn thế. Nhiều giao thức ứng dụng có port mặc định: HTTP là 80, HTTPS là 443.

Vào google.com, thanh địa chỉ có tiền tố HTTPS, và bạn không cần gõ port vì mặc định của HTTPS là 443 — dùng ngầm. Server gửi dữ liệu về client qua một port không nhất thiết là 443; với client, port nào cũng được, nên giao thức gán ngẫu nhiên và trình duyệt giữ port đó, ví dụ 7123.

Hình 6 — Request tới port 443 của server, response về port ngẫu nhiên của client

localhost là tên đặc biệt của IP 127.0.0.1, IP dành riêng trỏ về chính máy của bạn, dùng để truy cập server đang chạy local.

▸ Ví dụ của nguồn — demo Angular trên localhost
http://localhost:4200     // app Angular mặc định → chạy được
http://127.0.0.1:4200     // giống hệt localhost
http://localhost:4201     // lỗi: không có app nào ở port này
// mở terminal thứ hai trong VS Code, chạy lại app:
// "port 4200 is already in use" → đề nghị dùng port khác

Một port chỉ phục vụ được một ứng dụng tại một thời điểm.

Ôn tập · Tự kiểm tra

Năm câu hỏi

IPv4 dài bao nhiêu bit, chứa khoảng bao nhiêu địa chỉ? IPv6 thì sao?

32 bit, khoảng 4 tỉ địa chỉ. IPv6 dài 128 bit. (→ 01)

IP header chứa gì, TCP header thêm gì?

IP header: source IP, destination IP. TCP header thêm sequence number để ráp packet đúng thứ tự. (→ 02, 03)

HTTP, TCP, IP lần lượt ở tầng nào?

Application layer, transport layer, network layer. (→ 04)

Vì sao server thường cần static IP còn client thì không?

Client phải luôn gọi được server tại một địa chỉ cố định; không ai gọi tới client nên IP của nó đổi cũng không sao. Server dynamic IP vẫn chạy được nhờ dynamic DNS. (→ 06)

Port là bao nhiêu bit, mỗi máy có khoảng bao nhiêu port? localhost là IP nào?

16 bit, khoảng 65.000 port. localhost = 127.0.0.1. (→ 07)
